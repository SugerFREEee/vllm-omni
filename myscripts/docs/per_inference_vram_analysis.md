# temp1.nsys-rep 单次推理显存峰值分析

## 数据来源
- 原始文件：`third_party/vllm-omni/nsys/temp1.nsys-rep`
- 导出格式：通过 `nsys export -t sqlite --force-overwrite=true -o temp1 temp1.nsys-rep` 得到的 SQLite（`third_party/vllm-omni/nsys/temp1`）

## 转换与查询步骤
1) 导出：`nsys export -t sqlite --force-overwrite=true -o temp1 temp1.nsys-rep`
2) 表定位：显存事件表 `CUDA_GPU_MEMORY_USAGE_EVENTS`，NVTX 范围表 `NVTX_EVENTS`。  
   - `memKind` 映射：2 表示 Device 显存  
   - `memoryOperationType`: 0=Allocation, 1=Deallocation
3) 累积曲线：按时间对显存事件累加，得到时刻 in_use（bytes）。
4) 单次推理峰值：对每个 `vllm_server.omni_generate` 的 NVTX 范围，取该区间内以及进入区间前的显存占用最大值，换算为 MB。主要 SQL 片段：
```sql
WITH mem AS (
  SELECT start ts,
         CASE memoryOperationType WHEN 0 THEN bytes ELSE -bytes END AS delta
  FROM CUDA_GPU_MEMORY_USAGE_EVENTS
  WHERE memKind = 2
  ORDER BY ts
), c AS (
  SELECT ts, SUM(delta) OVER(ORDER BY ts) AS in_use FROM mem
)
SELECT n.start, n.end,
       (SELECT MAX(val) FROM (
          SELECT COALESCE((SELECT MAX(in_use) FROM c WHERE ts BETWEEN n.start AND n.end),0) AS val
          UNION ALL
          SELECT COALESCE((SELECT in_use FROM c WHERE ts<=n.start ORDER BY ts DESC LIMIT 1),0)
       )) / 1048576.0 AS peak_mb
FROM NVTX_EVENTS n
WHERE n.text = 'vllm_server.omni_generate'
ORDER BY n.start;
```

- 显存：加载完成基线约 1.292 GB；推理峰值 1.364–1.396 GB；单次推理额外显存开销约 72–104 MB。
- GPU 计算：推理前利用率≈0%；单次推理窗口 busy% 多数在 69–94%，但整体（含窗口间间隙）只有 ~22%；最大并行核数 4，说明单进程主要串行执行 kernel，重叠有限。
- 若需提高单进程吞吐，可考虑增加流/并发 kernel 或算子融合，但需权衡显存与调度开销。

```bash

  --trace=cuda,nvtx,osrt \
  --capture-range=nvtx --capture-range-end=stop \   # 用 NVTX 标记推理段，避免长时间采集
  --gpu-metrics-device=all \                        # 采集 SM/DRAM 等硬件计数器

  --cpuctxsw=process-tree \                         # 观察 CPU 线程/调度

  --force-overwrite=true \
  -o nsys_single_engine_full \
  <你的启动命令，保持 NVTX 标注>
```
- 如果需要更多同步/阻塞上下文，可同时开启 `--sample=process-tree --event-sample=process-tree`（有少量开销）。
